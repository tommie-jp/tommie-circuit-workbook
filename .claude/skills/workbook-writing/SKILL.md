# 教科書の題を書く

置き場・front matter・本文の順・部品の値・電源は、ルートの `README.md` の「書き方」が正本。
ここには、題を足すときの手順と、段と周波数の決まりをまとめる。

## 1. 段と周波数の範囲

必須 ⊂ 入門 ⊂ 中級 の入れ子。段ごとに、題で扱う周波数の上限を次のようにそろえる。

| 段 | 周波数 | 計器 | 基板 |
| --- | --- | --- | --- |
| 必須 | 3 MHz 以下 | AD3 のオシロ・波形発生器・スペクトラム | ブレッドボード |
| 入門 | 3 MHz 以下 (必須と同じ) | 同上 | ブレッドボードか perfboard |
| 中級 | 制限なし。ただし 01-circuits の README の基板ごとの範囲に従う (10 MHz 超は銅張り基板) | tinySA・VNA を足してよい | 範囲による |

- **入門までの題は、信号の周波数を 3 MHz 以下に絞る**。ブレッドボードの浮遊容量と AD3 のオシロの帯域 (9 MHz) の内側で、組んだとおりに測れるから。初めて組む人が「合わない」原因を配線ミスだけに絞れる
- 既に必須・入門に置いてある FM 帯の題 (9-4 FM 送信機・9-6 超再生 FM ラジオ) は、題材が FM 放送帯で、銅張り基板に組むので例外。書き足すときも同じ扱いにする
- 3 MHz を超える題 (FM・27 MHz・GHz 帯・DDS の 7 MHz など) は中級に置く。入門に置くなら、超える理由を題に 1 行書く
  (例: 「FM 放送帯の超再生は 3 MHz 以下では題が成り立たない」)
- 中波ラジオ (0.53〜1.6 MHz) と IF 455 kHz は 3 MHz 以下なので入門に置ける
- 例外: NanoVNA の冊は測る帯域そのものが題材なので、この冊は 3 MHz の絞りを課さない
  (入門では低い帯域の題から始め、GHz 帯は中級に寄せる)
- 部品の形 (リード・チップ・手巻き) は帯域で選ぶ。表は `01-circuits/README.md` の「基板ごとの使える範囲」にある
  「部品の形と周波数の範囲」。目安は SRF の 1/4 以下。30 MHz までのアキシアル・リード品はそのまま使え、
  チップ部品は銅張り基板の題 (30 MHz 超) に置く
- 掃引や FFT の表示範囲が 3 MHz を超えても、**回路が働く周波数**が 3 MHz 以下ならよい
  (高調波・像を見るために 10 MHz まで見る、など)。そのときは本文に見る範囲を書く

### 回路の規模の上限 (どの段も)

中級までの題は、読者が組んで、動かないときに自分で原因を絞れる規模にとどめる。
**数の上限**と、**規模以外の条件**の両方を満たす。満たさない題は教科書に置かず、`archive/` に置くか書かない
(2026-10-22 に決めた。きっかけは DRAM の配列とリフレッシュ。`archive/01-dram/`)。

| 物 | 上限 (1 題で) | 数え方・根拠 |
| --- | --- | --- |
| ブレッドボード | **新しく組むのは full 2 枚まで**。前の題の板を使い回して合計 3 枚まで | half は full 1 枚に数える。CPU もどき (1-1・1-4) が 2 枚 |
| ユニバーサル基板 | **5×7 cm を 3 枚まで** | 大きい板は 5×7 cm の何枚ぶんかで数える。半田付けはブレッドボードより密に組めるので 1 枚多く許す |
| IC | **新しく足す IC は 6 個まで** | DIP・SIP の IC と、IC の載ったモジュールを数える。前の題の基板にある IC は数えない |
| 基板の間の信号の線 | **12 本まで** (8 ビットのバスと制御 4 本) | 線の名前の数で数える (同じ信号を 4 か所へ配るのは 1 本)。電源・GND・計器 (AD3 など) の線は数えない。1-4 が 11 本 |

規模以外の条件 (どれかに当たれば、数が収まっていても外す):

1. **新しい原理が 1 つある**。前の題と同じ部品を数だけ増やす題は書かない (配列にする話は、前の題の読み物で済ませる)
2. **動かないとき、原因を基板 1 枚 (まとまり 1 つ) に絞る手順が書ける**。まとまりごとに単独で動くことを確かめる手順を本文に置く
3. **作者が実機で組んで測る見込みがある**。見込みの無い題は教科書に置かない

上限を超えても置く題 (例外) は、超える理由を題に 1 行書き、ここの表に足す。

| 題 | 超える物 | 置く理由 |
| --- | --- | --- |
| 05-etc 2-5 時計 | IC 13 個 (実体配線図のある 3 ユニットだけで)、ユニバーサル基板 15×9 cm 2 枚と 9×7 cm 2 枚 (5×7 cm で約 11 枚ぶん) | ユニット (発振と分周・窓判定・同期済みと設定) に分かれていて、ユニットごとに単独で確かめられる (条件 2)。ただし上限を大きく超えるので、ユニットごとに題を分けるかは未決 |

## 2. 題を足す手順

1. `<NN-冊>/plan.yaml` に 1 行足す (`id` `tier` `board` `title`)。既存の題と同じ型 (部品表・回路図・実体配線図・AD3・scope)
2. 同じ章の手本の題を 1 つ開き、本文の順をそろえる (説明 → 回路図 → 実体配線図 → 計器の設定 → 見るべき値 → 出典)
3. 部品の値は E24、電源は 5 V。外すときは部品表に理由を 1 行
4. **数式と数値は確かめる**。LTspice (または ngspice) で解析し、表の値と突き合わせる。確かめていない値は「見積り」と書く
   Pico 2 のプログラムは `tests/pico/` (層 A: SDK のモック、A': MicroPython のスタブ) で表の値と突き合わせ、題に `## プログラムでの確かめ` を置く
5. 図は tommie-fence スキルと readable-schematic・breadboard-wiring・instrument-screen の点検表を通す。
   `npm run render` で出した SVG を PNG にして目で見る (check はつながりしか見ない)
   フェンスの閉じの下の画像の行と、フェンスの 1 行目の名札のコメント
   (`# 回路図 (tommie-fence の circuit フェンス)`) は `npm run figures` が書く。**手で書かない・直さない**
   (フェンスを足した・動かしたら `npm run figures`。`check` が古さを言う)
   **ユニバーサル基板の図では、キットやモジュールの基板・面実装の変換基板に、ユニバーサル基板 (緑) と別の色を書く**
   (`J1: sip8 f16 r90 105404 blue`・`U1: dip4 n13 3SK291 blue`)。既定は実物の緑で、ユニバーサル基板と同じ色だと
   部品の基板の縁が読めない。標準は `blue`。もとから緑でない物 (USB の紺・SFU455B の橙) とブレッドボード (白) には書かない
6. 実体配線図・AD3・scope を入れない題は、理由を題に 1 行 (理由になることは README の「書き方」の表)
7. `npm run toc` で目次を直し、`npm run all` を通す。コミットは conventional commits (`docs:`)

## 3. 言葉

- 基板は「基板」か物の名前 (ブレッドボード・ユニバーサル基板・銅張り基板) で呼ぶ。単に「板」と書かない
- 部品のピンは「ピン」と書く。「足」と書かない
- 「ひずみ」は漢字 (歪み)・「センサー」は長音を付ける (README の用語の統一)
- 文書のギリシャ文字 (Γ・Ω・µ・π・τ など) は、**その文書で最初に出てくる所に読みを ( ) で添える** (例: 反射係数 Γ (ガンマ)、50 Ω (オーム))。2 回目からは書かない。frontmatter と題の見出しは数えず、本文の最初で数える。単位の Ω (オーム) や接頭辞の µ (マイクロ) も同じ、題名だけでなく `tommie-circuit-workbook` からの相対パスを書く
- 借りた回路は `source` と本文の出典に出所を書き、図と文は写さず描き直す
- **出典には URL を付ける。** 名指しした出所はその語にリンクを埋め込み、「自作。」だけの題は下に `参考: [題名](URL)、…` を 1 行足す。URL は curl などで 200 を確かめてから書き、403・404 のものは付けない (README の「書き方」)
- **単位の書き方は README の「単位の書き方」に従う。** 数と単位の間は空白を 1 つ (`10 kΩ`・`100 kHz`・`25 °C`)、
  マイクロは µ (U+00B5)、`µs` (`us` と書かない)、温度は `°C`、p-p は `Vpp`、ピークは `V<sub>p</sub>`。フェンスの中の値は各フェンスの綴り
  (`10kHz` のように詰める) に従う。2026-10-14 に決め、本文 1,900 行ほどを機械的に揃えた
- 英語版 (`en/`) でも同じ規則に従う。決めと用語は `en/GLOSSARY.md` (下の 4)
- **スペクトラム (`spectrum` フェンス) の縦軸の単位は dBm にそろえる。** FFT 型 (`ad2` `ad3`) の
  上流の既定も dBm (spectrum-fence 0.5.0 から。0.4.0 までは FFT 型だけ dBV だった) だが、
  版が違っても同じ数になるよう `unit: dBm` を明示し、`ref:` `floor:` `signal:` も dBm で書く
  (dBV と dBm は +13.01 dB 違うので、本文の数と図が食い違わないようにする)。
  dBV で書いてよいのは、**dBV そのものを教える題** (汎用オシロの Math の FFT の読み方。
  04-denken/03-ac-circuits/13-square-wave-fft.md) と、マイクの感度 `dBV/Pa` のような単位の一部だけ。
  理由を本文に 1 行書く
  (2026-10-14 に決め、同日に既存の図 29 枚 (`unit: dBV` の 12 枚と、`unit` を書かない AD の FFT 型 17 枚) を
  dBm に直した。本文の dBV の数も +13.01 dB で換算済み。AD の Spectrum の章は「単位: dBm」と教える)

## 4. 英語版 (`en/`) を訳す・直す

**日本語の題が原本。英語は訳で、英語だけを直さない** (直すときは日本語を直して訳し直す)。決めと用語は
`en/GLOSSARY.md`、検査は `npm run en:check` (`npm run all` に入る)、一覧は `npm run i18n:stale`。
訳さない冊は 04-denken (試験の範囲と JIS の記号が前提)。

1. **訳す前に読む**: `en/GLOSSARY.md`・この skill の 1〜3・README の「単位の書き方」・tommie-fence skill
   (フェンスの綴り)・図の描画 skill (readable-schematic・breadboard-wiring・perfboard-wiring・copper-board・
   instrument-screen・readable-graph)。日本語の規則 (基板・ピン・信号発生器と発振回路の書き分け・単位・
   Greek 文字) は英語でも同じ決めを `en/GLOSSARY.md` に置いてある
2. **置き場と front matter**: `en/<冊>/<章>/<題>.md` (日本語と同じ名前)。front matter は日本語の題の鍵と値を
   全部写し、**`title` だけ英語**にして、`ja: <日本語の題の git blob hash>` を足す (`git hash-object <日本語の題>`)。
   最初の見出しは `# <id> <title>`
3. **本文**: 順と節は日本語と同じ (節の見出しは GLOSSARY の表)。事実・数値・出典を足さない・落とさない。
   測った値の `.s2p` や CSV は写さず、`data:` で日本語の側の物を相対パスで指す。コードは同じ物を置き、
   **コメントだけ訳す**
4. **図**: フェンスの部品・値・番地・配線・`board:` `device:` は変えない。訳すのは `title:`・注釈・人が読む字だけ。
   `en-check` が日本語の図との差を見る。訳したら `npm run render -- --en` で SVG にして PNG にし、
   **点検表を通して目で見る** (英語は日本語より長いことが多い。札の重なり・図からのはみ出しを見る。
   `circuit` の `title:` は 60 字まで)。名札の行と画像の行は `npm run figures` が書く (手で書かない)
5. **単位・用語**: 日本語と同じ (`10 kΩ`・`µs`・`°C`・`Vpp`・`V<sub>p</sub>`・spectrum は dBm)。`en-check` が見る
6. **日本語を直したら**: `ja:` の hash が古くなる。`npm run i18n:stale` で一覧し、訳し直して `ja:` を更新する
   (警告で、落とさない)
7. **進め方**: 冊ごとに「訳す → 別の目で日本語と突き合わせて見直す → `npm run en:check` と `npm run all` →
   コミット (`docs:`)」。冊を並行しない。英語の目次 (`en/README.md`) は `npm run toc` の対象にまだ入っていない
