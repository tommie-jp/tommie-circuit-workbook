# 8-16 湿度 (DHT)

DHT11 は、湿度と温度を測って、1 本の線 (DATA) で数字として送り出すセンサーである。中には、湿度で抵抗の変わる素子と
サーミスタ (8-2) と、小さなマイコンが入っている。同じ形の上位の品に DHT22 (AM2302) がある。

DHT11 の DATA は **1 本で送りも受けもする** (単線双方向)。ふだんは抵抗で H に引き上げておき、使う側 (マイコンなど) が

1. DATA を **18 ms 以上 L** にする (開始の合図)
2. 放すと、DHT11 が **80 µs の L と 80 µs の H** で返事をする
3. 続けて **40 ビット** (湿度 8 ビット・湿度の小数 8 ビット・温度 8 ビット・温度の小数 8 ビット・検査の 8 ビット) を送る。
   どのビットも 50 µs の L で始まり、その後の **H の長さ**で 0 (約 26〜28 µs) か 1 (約 70 µs) を表す

という決まり (データシートの「単線の通信」) で読む。40 ビットで約 4 ms かかる。

この題では、マイコンの代わりに Analog Discovery 3 (AD3) の W1 で開始の 20 ms の L を作り、DATA の波形をオシロで見て、
H の長さから 40 ビットを手で読み、湿度と温度に直す。データシートの決まりを、波形で確かめるのが目的である。
マイコン (Pico 2) で読む方法は、11-5 の I2C の温度センサーと同じく、11 章の題で扱う。

## 回路図

```circuit
# 回路図 (tommie-fence の circuit フェンス)
title: 図1 DHT11 の DATA を 4.7 kΩ で引き上げ、W1 の 20 ms で Q1 が L に引く
parts:
  U1:
    type: device
    model: DHT11
    at: 2,3
    pins: [VCC, DATA, GND]
    turn: mirror
  VCC: vcc 4.5,1 3.3V
  G1: ground 3.6,5
  RP: resistor 7,1 7,3 4.7k
  Q1: npn 8,5.5
  G2: ground 8,7.5
  M1: voltmeter 10,3 10,5 l=$\mathrm{CH1}$
  G3: ground 10,5
  C1: capacitor 12,1 12,3 100n
  G4: ground 12,3
  W1: square 3,8 3,10 l=$\mathrm{W1}$
  G5: ground 3,10
  M2: voltmeter 4.5,8 4.5,10 l=$\mathrm{CH2}$
  G6: ground 4.5,10
  RB: resistor 5.5,8 7.5,8 10k
wires:
  - U1.VCC -| 4.5,1
  - 4.5,1 -- 7,1 -- 12,1
  - U1.DATA -- 7,3 -- 8,3 -- 10,3
  - 8,3 -- Q1.C
  - U1.GND -| 3.6,5
  - Q1.E -- 8,7.5
  - 3,8 -- 3,7 -- 4.5,7
  - 4.5,7 -- 4.5,8
  - 4.5,7 -- 5.5,7 -- 5.5,8
  - 7.5,8 -- 7.5,5.5
  - 7.5,5.5 -- Q1.B
style:
  grid: on
  pitch: 1.2
```

![回路図](https://tommie-jp.github.io/tommie-circuit-workbook/01-circuits/08-sensors/circuit/16-dht11.svg)

- **RP (4.7 kΩ)**: DATA を 3.3 V に引き上げる。DHT11 も Q1 も、DATA を L に**引くだけ** (開放コレクタと同じ使い方) なので、
  どちらも引かないときに H になるよう、抵抗が要る。データシートは線が 20 m より短いとき 5 kΩ を勧めている (E24 の 4.7 kΩ にした)
- **Q1 (2SC1815) と RB**: W1 が H (3.3 V) の間、ベースに (3.3 − 0.7) V ÷ 10 kΩ ≈ 0.26 mA が流れ、Q1 は DATA を約 0.05 V まで引き下げる。
  W1 を DATA に直接つながないのは、DHT11 が返事を送る間に W1 が DATA を H に押さえてしまうため (Q1 は L に引くか放すかだけで、H は押さえない)
- **W1 は 1 Hz・幅 20 ms のパルス**にする。W1 が H の 20 ms の間 DATA が L になり (開始の合図)、W1 が L に戻ると DATA が放される。
  1 秒に 1 回なので、データシートの「測る間隔は 1 秒以上」も守れる
- **電源は 3.3 V**。DHT11 は 3〜5.5 V で動く。AD3 の Logic (デジタルの入力) で DATA を取り込むとき、論理の電圧 3.3 V に合わせておくため
- C1 (0.1 µF) は DHT11 の電源のデカップリング (データシートの応用の回路にも入っている)

  - j10 -- -b10 black

![ブレッドボードの実体配線図](https://tommie-jp.github.io/tommie-circuit-workbook/01-circuits/08-sensors/breadboard/16-dht11.svg)

- 3.3 V は AD3 の Supplies の V+ (WaveForms で 3.3 V にする) から上の + レールへ。上下の − レールを左端でつなぐ
- **DHT11 (U1)** は青い格子の面を手前にして、上のブロックの列 10〜13 に挿す。左から VCC・DATA・NC・GND。VCC (列 10) を + レールへ、
  GND (列 13) を − レールへ。C1 は列 18〜21 (18 列を + レール、21 列を − レールへ) で、DHT11 のすぐ横の電源に入れる。3 番の NC は何もつながない
- **RP**: DATA の列 11 (`d11`) から列 16 へ、列 16 を + レールへ
- **Q1 (2SC1815)** は印字の面を手前にして、下のブロックの列 10〜12 に E・C・B の順。E (列 10) は − レールへ。C の列 11 は黄の線 `e11 -- f11` で上の DATA の列 11 へ
- **RB**: B の列 12 (`i12`) から列 17 へ。W1 (緑) を `j17` に挿し、緑の線で列 20 へ延ばして CH2 (2+) をそこに当てる
- オシロの CH1 (1+、黄) は DATA の列 11 の下 (`j11`)
- 電流は DHT11 の測る間の 0.5〜2.5 mA、RP の 0.7 mA (DATA が L の間)、Q1 のベースの 0.26 mA (W1 から)。AD3 の範囲とブレッドボードの範囲に十分収まる

## 計器の設定

計器は AD3。Supplies の V+ を 3.3 V。W1 を Pulse (方形波で対称を 2 %) ・1 Hz・0〜3.3 V にして、1 秒に 1 回 20 ms の H を出す。
Scope は CH1 を DATA、CH2 を W1 にして、まず横 5 ms/div・縦 1 V/div で全体を見る。トリガは CH2 の立ち上がり 1.65 V、トリガの位置は左から 1 目盛。

見えるはずの画面 (W1 の 20 ms と、DHT11 の返事と 40 ビットの塊。塊の中の細かい形は目安で、実測ではない)。

```scope
# オシロスコープの画面 (tommie-fence の scope フェンス)

time: 5ms/div
trigger: ch2 rising 1.65V at -4div
ch1: {wave: "= 3.3V * (1 - step(t) + step(t - 20ms)) - 3.3V * (step(t - 20.03ms) - step(t - 23.87ms)) * clip(100 * sin(2 * pi * 10kHz * t), 0, 1)", range: 1V/div, position: 0div}
ch2: {wave: "= 3.3V * (step(t) - step(t - 20ms))", range: 1V/div, position: -4div}

measure: [vmax, vmin]
```

![オシロスコープの画面](https://tommie-jp.github.io/tommie-circuit-workbook/01-circuits/08-sensors/scope/16-dht11.svg)

- CH1 は W1 が H の 20 ms の間 L (約 0.05 V)。カーソル X1・X2 の差が開始の合図の長さ (データシートの「18 ms 以上」を満たす)
- W1 が L に戻ると、DATA はいったん H に戻り、約 30 µs 後に DHT11 が返事を始める。そこから約 4 ms、細かい L と H が並ぶ
- 細かい所は、横を 500 µs/div にし、トリガを CH2 の立ち下がり (トリガの位置は左から 1 目盛) に替えて見る。図4 は、同じ所を AD3 の Logic で
  取り込んだときに見えるはずの 0 と 1 (DIO 0 を DATA につなぎ、DIO 0 の立ち下がりでトリガ)

![ロジックアナライザの画面](https://tommie-jp.github.io/tommie-circuit-workbook/01-circuits/08-sensors/logic/16-dht11.svg)

図4 の読み方 (湿度 55 %RH・温度 24 °C と**仮定**して作った並び。実測ではない):

- 最初の L (80 µs) と H (80 µs) が返事。その後の 40 個の H の長さを、短い (約 27 µs) = 0、長い (約 70 µs) = 1 と読む
- カーソル X1・X2 は 3 ビット目の H で、ΔX は 70 µs (1)。最初の 8 ビットは 0011 0111 = 0x37 = **55** (湿度 55 %RH)
- 次の 8 ビットは 0 (DHT11 の湿度の小数は 0)、その次の 8 ビットは 0001 1000 = 0x18 = **24** (24 °C)、温度の小数も 0
- 最後の 8 ビットは 0100 1111 = 0x4F。**検査**: 0x37 + 0x00 + 0x18 + 0x00 = 0x4F で一致するので、読み違いがない

## LTspice での確かめ

DHT11 の中 (センサーとマイコン) は SPICE の対象外。`sim/16-dht11.cir` で Q1 と RP の側 (開始の合図) だけを解き、ビットの並びと検査は算術で確かめた。
DATA の線の容量は 50 pF と仮定した。

| 項目 | 本文の数字 | LTspice / 算術 | 判定 |
| --- | --- | --- | --- |
| DATA の L (W1 が H) | 約 0.05 V | 0.045 V | 合う |
| DATA の H (待っている間) | 3.3 V | 3.30 V | 合う |
| Q1 のベース電流 | 約 0.26 mA | 0.264 mA | 合う |
| L の長さ | 20 ms | 20.0 ms | 合う |
| 放したときの立ち上がり (10〜90 %) | 1 µs 以下 | 0.57 µs | 合う (ビットの 27 µs より十分短い) |
| 40 ビットの長さ (図4 の並び) | 約 4 ms | 返事の始まりから 3.81 ms (算術) | 合う |
| 検査 | 0x37 + 0x18 = 0x4F | 0x4F (算術) | 合う |

0 と 1 の H の長さ (26〜28 µs・70 µs) はデータシートの図の値で、図4 の並びはそれを使って作った。実物の DHT11 の値は個体で数 µs ずれる。
